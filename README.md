## Реализация

Считается, что агент попадает на мисию в момент времени $t_0$, после чего может либо отмотать время назад, либо подожать нужного времени старта. В следствие чего, в алгоритме раcсматриваются только $t_0 \le 0$

Солвер написан в виде класса MissionSolver. В него передается указатель на класс MissionSolver::Request, в котором хранится вся нужная информация. При передаче проверяется корректность, если не корректно кидается исключение. Поиск ответа осуществляется методом CheckMission(). Он возвращает объект класса MissionSolver::Response, в котором лежит ответ.

Ответ находится так:\
Так как артефактов не очень много, можно завести граф, вершины которого характеризуются парой (узел; маска артефактов, которые есть во время нахождения в узле).\
 Ребро проводится:

- между вершинами с равной маской, если есть ребро в запросе и оно удовлетворяет требованию `artifact`, длина нового ребра совпадает со старым, ограничение равно ограничению ребра
- между вершинами с ранвым узлом и масками, отличающимеся на артефакт, который лежит в этом узле, длина ребра равна 0, ограничение равно ограничению артефакта

После этого запускается алгоритм Дейкстры со стартовым временем $t_0$. Он выдает массив с расстояниями до каждой вершины. Метод RecalculateResponse() выбирает финишные узлы, проверяет, что время не больше t_lim и обновляет ответ, если он лучше.

Возможные стартовые $t_0$ находит метод CalculatePossibleStartTimes(). Он идет от обратного от каждого ребра и вычисляет, не позже какого времени нужно стартовать, чтобы была возможность пройти по ребру.

## Асимптотика

Пусть $V$ -- количество узлов, $E$ -- переходов, $k$ -- артефактов.

Тогда вершин в нашем графе $V' = V \cdot 2^k$, ребер $E' \le E \cdot 2^k + k\cdot2^k$.

Поиск возможных $t_0$: $O(E'^2 \log(V'))$\
Финальные запуски Дейкстры $O(E'^2 \log(V'))$

Итого: $O(E'^2 \log(V')) = O(2^{2k}(E+V)^2 \log(V2^k))$
